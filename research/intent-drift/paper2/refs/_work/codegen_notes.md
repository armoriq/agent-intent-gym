# Cluster: codegen (code-generation benchmarks, test sufficiency, contamination)

### chen2021evaluating: Evaluating Large Language Models Trained on Code
Source checked: https://arxiv.org/abs/2107.03374 (v2), https://arxiv.org/bibtex/2107.03374, https://arxiv.org/pdf/2107.03374
Introduces Codex and the HumanEval set of 164 hand-written Python problems with an average of 7.7 unit tests each (Section 2.2), and defines functional correctness via pass@k: generate n >= k samples per task (n = 200, k <= 100 in the paper), count the c correct ones, and use the unbiased estimator pass@k = E_problems[1 - C(n-c, k) / C(n, k)] (Section 2.1, Eq. 1, numerically stable code in Figure 3, bias of the naive 1-(1-p)^k estimator shown in Appendix A). Codex-12B reaches 28.81% pass@1, 46.81% pass@10 and 72.31% pass@100 on HumanEval (Table 1; 28.8% also in the abstract). Appendix E.2 defines a model as "intent misaligned" when it outputs B where the user would prefer A, while being capable of producing A and of distinguishing the two situations. Background: pass@k on visible unit tests is the metric our drift gap is measured against, and the Appendix E definition of intent misalignment is a direct conceptual ancestor of our "intent drift".

### austin2021program: Program Synthesis with Large Language Models
Source checked: https://arxiv.org/abs/2108.07732 (v1), https://arxiv.org/bibtex/2108.07732, https://arxiv.org/pdf/2108.07732
Introduces MBPP, 974 crowd-sourced entry-level Python tasks each with a description, reference solution and three assert-based test cases (Section 2.1), and reports 59.6% few-shot solve rate for the largest (137B) model (abstract, Section 1). Section 4.4 writes adversarial "challenge" tests for 50 of the 500 test problems: solve rate falls from 66% on the normal tests to 58% with challenge tests, so roughly 12% of counted solutions do not generalize (Figure 7 shows a task where all samples delete every occurrence of a character instead of the first and last). Section 4.5 and Figure 8 document a model hard-coding `if n == 383: return True` to pass the visible asserts of the Woodall-number task. Method precedent: held-out challenge tests to measure the gap between passing visible tests and satisfying intent, at small scale and on single functions rather than agentic repository edits.

### liu2023evalplus: Is Your Code Generated by ChatGPT Really Correct? Rigorous Evaluation of Large Language Models for Code Generation
Source checked: https://arxiv.org/abs/2305.01210 (v3), https://arxiv.org/pdf/2305.01210, https://proceedings.neurips.cc/paper_files/paper/2023/hash/43e9d647ccd3e4b7b5baab53f0368686-Abstract-Conference.html, https://proceedings.neurips.cc/paper_files/paper/2023/file/43e9d647ccd3e4b7b5baab53f0368686-Bibtex.bib
EvalPlus augments HumanEval with LLM-seeded and type-aware-mutation test inputs (80x more tests) checked differentially against corrected ground truth, producing HumanEval+. Across 26 LLMs, pass@k drops by up to 23.1% (pass@1, greedy) / 19.3% (pass@1) / 24.9% (pass@10) / 28.9% (pass@100) (Section 3, "Evaluation of LLMs" paragraph, page 6, and Table 3; summarised as "up-to 19.3-28.9%" in the abstract and Section 1); GPT-4 greedy pass@1 goes from 88.4 to 76.2 (Table 3), and the same section reports that over 10% of the original HumanEval ground-truth solutions were incorrect. The paper also shows test insufficiency changes model rankings (WizardCoder-CodeLlama and Phind-CodeLlama overtake ChatGPT on HumanEval+). Method precedent: the closest precedent for our hidden tests, showing that adding unseen tests exposes code that passed the visible suite; we extend this from function synthesis to agentic bug fixing and add prompt-phrasing and scope dimensions.

### jain2025livecodebench: LiveCodeBench: Holistic and Contamination Free Evaluation of Large Language Models for Code
Source checked: https://arxiv.org/abs/2403.07974 (v2), https://arxiv.org/pdf/2403.07974 (v2), https://arxiv.org/pdf/2403.07974v1, https://api2.openreview.net/notes/search (record chfJJYC3iL), https://openreview.net/forum?id=chfJJYC3iL
LiveCodeBench collects LeetCode, AtCoder and CodeForces contest problems tagged with release dates so that each model can be scored only on problems released after its training cutoff. In arXiv v2 (6 Jun 2024), DeepSeek-Base-33B drops from about 60 pass@1 on May 2023 LeetCode problems to about 0 on September 2023 problems, and Codestral scores 36.5 pass@1 on problems from May 2023 to Jan 2024 versus 28.3 on problems since Feb 2024 (Section 5.1, Figure 1); Section 5.2 also reports a group of fine-tuned open models that do well on HumanEval+ but poorly on LiveCodeBench (Figure 5). All numbers here are from arXiv v2; the ICLR 2025 camera-ready PDF on OpenReview could not be downloaded (bot challenge), so its counts were not checked. Method precedent: release-date tagging relative to model cutoff is the basis for our fresh / post-cutoff / classic contamination tags.

### aleithan2024swebench: SWE-Bench+: Enhanced Coding Benchmark for LLMs
Source checked: https://arxiv.org/abs/2410.06992 (v2), https://arxiv.org/pdf/2410.06992 (v2), https://arxiv.org/pdf/2410.06992v1, https://api2.openreview.net/notes/search (records pwIGnH2LHJ, R40rS2afQ3, DmUaCItx3J)
Manually audits the 251 SWE-bench (full) instances that SWE-Agent + GPT-4 resolved: 82 (32.67%) are solution leakage, where the fix is spelled out in the issue text or comments, and 78 (31.08%) pass only because of weak tests, split into incorrect fixes 12.75%, changes to different files or functions than the gold patch 3.59%, and incomplete fixes 14.74% (Table 1, Section 1 and Section 2.1). Section 1 also notes that 94% of SWE-bench instances predate the models' training cutoffs, and the newly collected SWE-bench+ (issues from 2023-11-01 to 2024-08-22, leakage filtered) drops SWE-Agent + GPT-4 to 0.55%. The filtered resolution rate is reported inconsistently: 3.97% (Section 1, Figure 1b) versus 5.49% (Section 2.2), so cite either with care. Supports: weak tests let incorrect or incomplete patches count as resolved, which is exactly the visible-pass / intent-fail gap we measure, and "different files/functions changed" is a small-scale analogue of our out-of-scope edits.

### liang2025swebench: The SWE-Bench Illusion: When State-of-the-Art LLMs Remember Instead of Reason
Source checked: https://arxiv.org/abs/2506.12286 (v4), https://arxiv.org/pdf/2506.12286 (v4), https://arxiv.org/pdf/2506.12286v1
Proposes diagnostic probes for memorization on SWE-Bench: predicting the buggy file path from the issue description alone, with no repository structure, and reproducing ground-truth functions verbatim. In v4, file-path accuracy reaches up to 76% on SWE-Bench Verified (range 60-76% across models), 57-71% on Full SWE-Bench, 50-68% on newly collected tasks from the same repositories, and is uniformly below 53% on Outside-Repo tasks from popular repositories not in SWE-Bench (Section 4.1, Figure 8); the gap persists after filtering out issues that mention the path (Section 4.2, Figure 9, Table 2). Consecutive 5-gram overlap when reproducing functions is up to 34.9% on SWE-Bench Verified versus up to 18.2% on other benchmarks (abstract, Section 4.3). Supports: evidence that SWE-Bench scores are inflated by memorization, motivating our post-cutoff and freshly written tasks.

### riddell2024quantifying: Quantifying Contamination in Evaluating Code Generation Capabilities of Language Models
Source checked: https://arxiv.org/abs/2403.04811, https://aclanthology.org/2024.acl-long.761/, https://aclanthology.org/2024.acl-long.761.bib, https://aclanthology.org/2024.acl-long.761.pdf
Matches the gold solutions of MBPP and HumanEval against The Pile and StarCoderData at surface and semantic level. Section 4.1 reports that 12.2% of HumanEval solutions and 3.6% of MBPP solutions have been seen in The Pile, versus 18.9% and 20.8% in StarCoderData (Figure 1). Models score far higher on the most-overlapping 10% of problems than on the least-overlapping 10%, e.g. StarCoderBase-15.5B 72.0% versus 22.0% on MBPP (Table 2), and removing likely contaminated items lowers accuracy, e.g. Pythia-12B on HumanEval by up to 82.7% relative (Table 1). Supports: quantitative evidence that classic code benchmarks are contaminated, justifying our "classic" tag as a separate stratum rather than a clean baseline.

### matton2024leakage: On Leakage of Code Generation Evaluation Datasets
Source checked: https://arxiv.org/abs/2407.07565 (v3), https://aclanthology.org/2024.findings-emnlp.772/, https://aclanthology.org/2024.findings-emnlp.772.bib, https://aclanthology.org/2024.findings-emnlp.772.pdf
Argues HumanEval and MBPP are contaminated through direct leakage, through synthetic training data, and through checkpoint selection on the test sets (Section 3), noting every HumanEval prompt appears at least 43 times on public GitHub (median 99, Figure 1). It releases LBPP, 161 new human-written problems built with a model in the loop, on which leading HumanEval and MBPP models score up to 43% and 27% lower, with rankings changing (Section 4, Table 2). Supports: freshly authored tasks are needed for uncontaminated measurement, which is the rationale behind our "fresh" tasks.

### zhu2025establishing: Establishing Best Practices in Building Rigorous Agentic Benchmarks
Source checked: https://arxiv.org/abs/2507.02825 (v5), https://arxiv.org/pdf/2507.02825 (v5), https://proceedings.neurips.cc/paper_files/paper/2025/hash/f316275b44ee2de533102913828a8107-Abstract-Datasets_and_Benchmarks_Track.html, https://proceedings.neurips.cc/paper_files/paper/2025/file/f316275b44ee2de533102913828a8107-Bibtex-Datasets_and_Benchmarks_Track.bib, https://api2.openreview.net/notes/search (record E58HNCqoaA)
Proposes the Agentic Benchmark Checklist (ABC), built around task validity (a task is solvable iff the agent has the target capability) and outcome validity (the evaluation result truly indicates task success), drawing on 17 widely used agentic benchmarks (Section 1, Table 3). Applying ABC to ten benchmarks finds seven with outcome-validity flaws, seven with task-validity flaws and all ten with reporting limitations (Section 1, Figure 5); examples include SWE-bench Verified's insufficient unit tests (Appendix assessment report, citing UTBoost), tau-bench counting empty responses as success so a trivial agent scores 38% (Section 1), and estimation errors of up to 100% in relative terms. Revising CVE-Bench with ABC cut performance overestimation by 33% in absolute terms (Section 1; Section 5.3 itemizes 32.5% from SLEEP-clause matching and a 10% success-rate drop from closing an outbound-server shortcut). Supports: our hidden tests are an outcome-validity fix, and our prompt-phrasing and rabbit-hole dimensions probe task validity, in the terms this paper defines.
