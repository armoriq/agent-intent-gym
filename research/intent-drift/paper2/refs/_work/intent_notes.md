# Cluster: intent

### zhou2023instructionfollowing: Instruction-Following Evaluation for Large Language Models
Source checked: https://arxiv.org/abs/2311.07911 (export API), https://arxiv.org/html/2311.07911
IFEval scores instruction following with "verifiable instructions" (for example word counts, keyword frequency, JSON output) that a deterministic program can check, so no human or LLM judge is needed. The abstract says "25 types" and "around 500 prompts". The body is more exact: "a list of 25 verifiable instructions" and "a set of 541 prompts", each with one or more instructions (Section 1 Introduction; the 25 types are listed in Table 1). Prompt-level and instruction-level strict and loose accuracy are defined in Section 2.2 and Section 3. Method precedent: IFEval checks the stated surface constraints of a prompt programmatically. Our hidden intent tests do the same job for the developer's unstated constraints, and the paper's own caveat (Section 1) that "very few instructions are 100% verifiable" supports why we keep a separate rubric layer.

### sharma2024towards: Towards Understanding Sycophancy in Language Models
Source checked: https://arxiv.org/abs/2310.13548, https://arxiv.org/html/2310.13548, OpenReview API search (forum tvhaxkMKAn, venue "ICLR 2024 poster")
The paper shows that five AI assistants trained with human feedback are consistently sycophantic across four free-form tasks (abstract, Section 3). It traces part of the cause to preference data and preference models, which favour responses that match the user's beliefs (Section 4.1, Figure 5). In Section 3.2 ("Are you sure?" challenges), "Claude 1.3 wrongly admits mistakes on 98% of questions." Background: this is a mechanism by which RLHF-trained agents may optimise for what looks acceptable over what is correct, in line with our metric-versus-intent gap. Author list note: the OpenReview ICLR record lists 18 authors and omits Newton Cheng, who appears in the arXiv v4 list (19 authors). The bib follows arXiv.

### perez2023discovering: Discovering Language Model Behaviors with Model-Written Evaluations
Source checked: https://arxiv.org/abs/2212.09251, https://arxiv.org/html/2212.09251, https://aclanthology.org/2023.findings-acl.847.bib
The authors use LMs to generate 154 evaluation datasets covering persona, politics, ethics, sycophancy and advanced-AI-risk behaviours (Section 1). In Section 4.2 (Figure 4), larger models repeat back the user's stated view more often: "The largest (52B) models are highly sycophantic: > 90% of answers match the user's view for NLP and philosophy questions." RLHF does not remove this, and preference models actively reward it. Background: early large-scale evidence that models tailor outputs to a user's framing, which is relevant to how prompt phrasing (scoped / loose / vague) might steer agent behaviour. Published in Findings of ACL 2023, pp. 13387-13434, DOI 10.18653/v1/2023.findings-acl.847. The bib truncates the 63-author list after 10 names, as the brief allows.

### zheng2023judging: Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena
Source checked: https://arxiv.org/abs/2306.05685, https://arxiv.org/html/2306.05685, https://proceedings.neurips.cc/paper_files/paper/2023/hash/91f18a1287b398d378ef22505bf41832-Abstract-Datasets_and_Benchmarks.html (and its BibTeX)
The paper introduces MT-Bench and Chatbot Arena and tests strong LLMs as judges of open-ended answers. GPT-4 agrees with humans at over 80%. Under setup S2 (no ties), GPT-4 to human agreement on MT-Bench is 85% against 81% for human to human (Section 4.2, Table 5). Section 3.3 documents three biases. Position bias: GPT-4 is consistent under order swap in only 65.0% of cases with the default prompt, against 23.8% for Claude-v1 (Table 2). Verbosity bias: under the "repetitive list" attack, failure rates are 91.3% for Claude-v1 and GPT-3.5 and 8.7% for GPT-4 (the table is numbered Table 3 in the arXiv HTML, but the body text cites it as "Table 4"). Self-enhancement: GPT-4 favours itself by a 10% higher win rate and Claude-v1 by 25%, yet the authors say they "cannot determine" whether this is a true bias. Method precedent: if our rubric uses an LLM judge, we should swap answer order, control for length, and avoid using a judge from the same family as the agent being scored.

### mu2023clarifygpt: ClarifyGPT: Empowering LLM-based Code Generation with Intention Clarification
Source checked: https://arxiv.org/abs/2310.10996, https://arxiv.org/html/2310.10996
ClarifyGPT spots ambiguous code-generation requirements with a code-consistency check: it samples several solutions and compares their outputs on generated test inputs. When the requirement is ambiguous, it asks targeted clarifying questions before generating the final code (Section 3). In the human evaluation, GPT-4 Pass@1 on MBPP-sanitized rises from 70.96% to 80.80%, and on MBPP-ET from 51.52% to 60.19% (Section 5.1, Table 2). With simulated feedback, the GPT-4 average across four benchmarks goes from 68.02% to 75.75% (Section 5.2, Table 3). Supports: when requirements are underspecified, models code straight past them and drift from user intent, which motivates our vague-phrasing condition. Venue note: Crossref lists a version in Proceedings of the ACM on Software Engineering, Vol. 1, FSE (2024), DOI 10.1145/3660810, under a different title ("ClarifyGPT: A Framework for Enhancing LLM-Based Code Generation via Requirements Clarification"). The ACM DL page returned 403, so the bib keeps this as @misc arXiv.

### wu2025humanevalcomm: HumanEvalComm: Benchmarking the Communication Competence of Code Generation for LLMs and LLM Agent
Source checked: https://arxiv.org/abs/2406.00215 (Journal ref and DOI fields), https://arxiv.org/html/2406.00215
HumanEvalComm hand-edits the 164 HumanEval problem descriptions to be ambiguous, inconsistent, or incomplete, then measures whether code LLMs ask clarifying questions instead of producing code (Section 2.1). The "Answer to RQ1" box in Section 4.1 reports that more than 60% of responses still generate code without asking. Pass@1 falls by 35% to 52% and Test Pass Rate by 17% to 35% relative to the original descriptions. Supports: degraded or underspecified problem statements cut functional correctness sharply, and models rarely flag the gap, which is a direct precedent for our scoped/loose/vague manipulation. Published in ACM TOSEM, January 2025, DOI 10.1145/3715109 (confirmed via the arXiv journal_ref and DOI fields; the ACM DL page itself returned 403).

### vijayvargiya2026ambigswe: Ambig-SWE: Interactive Agents to Overcome Underspecificity in Software Engineering
Source checked: https://arxiv.org/abs/2502.13069, https://arxiv.org/html/2502.13069, OpenReview API search (forum X2yzXtH4wp, venue "ICLR 2026 Poster")
The authors take the 500 SWE-Bench Verified issues, use GPT-4o to write underspecified versions of each, and run OpenHands agents in three settings: Full, Hidden (underspecified, no interaction) and Interaction (underspecified, with a simulated user) (Sections 2.1 and 2.3). Interaction recovers up to 80% of Full-setting performance for the Claude Sonnet 3.5 and Haiku 3.5 models, 89% for Claude Sonnet 4, and only 59% and 54% for Deepseek-v2 and Llama 3.1 (Section 3.2). The abstract reports gains of up to 74% over the non-interactive setting. Without explicit prompting, models almost never ask questions, and Qwen 3 Coder had a 100% false-negative rate at detecting underspecification (Section 4.2). Method precedent and Supports: this is the closest prior work to our phrasing manipulation, since it pairs full and degraded versions of the same SWE task and measures the resolve-rate gap. Note that the title changed: arXiv v1 and dblp use "Interactive Agents to Overcome Ambiguity in Software Engineering", while v3 and ICLR use the Ambig-SWE title.

### laban2026llms: LLMs Get Lost In Multi-Turn Conversation
Source checked: https://arxiv.org/abs/2505.06120, https://arxiv.org/html/2505.06120, OpenReview API search (forum VKGTGGcwl6, venue "ICLR 2026 Oral")
Laban et al. split fully specified instructions into "shards" that a simulated user reveals one turn at a time, across six generation tasks including Code. They compare Full, Concat and Sharded settings in more than 200,000 simulated conversations (Section 3, abstract). Performance drops by an average of 39% in the Sharded setting (Section 6.1, Table 1), while Concat keeps 95.1% of Full, so the loss does not come from missing information. Aptitude falls only 16% while unreliability rises 112% (Section 6.2). The proposed causes are premature answer attempts and over-reliance on earlier wrong attempts (Appendix F). Supports: underspecification at the start leads models to commit to assumptions they do not revisit. Figure 1's caption gives "-35%" while the abstract and Section 6.1 give 39%, so cite 39% from Section 6.1.

### liu2024lost: Lost in the Middle: How Language Models Use Long Contexts
Source checked: https://arxiv.org/abs/2307.03172, https://arxiv.org/html/2307.03172, https://aclanthology.org/2024.tacl-1.9.bib
Using multi-document QA and key-value retrieval, the paper finds a U-shaped curve. Performance is best when the relevant information sits at the start or end of the context and worst when it sits in the middle (Section 2.3, Figure 5). GPT-3.5-Turbo's multi-document QA accuracy can drop by more than 20%, and in the 20- and 30-document settings it falls below its closed-book accuracy of 56.1% (Section 2.3, Table 1). Background: when a bug report or a scoped instruction sits deep in a long repository context, the agent may under-attend to it, which is one route to intent drift on long tasks. Published in TACL vol. 12, pp. 157-173, 2024, DOI 10.1162/tacl_a_00638.

### sinha2026illusion: The Illusion of Diminishing Returns: Measuring Long Horizon Execution in LLMs
Source checked: https://arxiv.org/abs/2509.09677, https://arxiv.org/html/2509.09677, OpenReview API search (forum 3lm8lWYxiq, venue "ICLR 2026 Poster"; an earlier version also appears as an MTI-LLM @ NeurIPS 2025 workshop poster)
The paper isolates long-horizon execution by supplying the plan and knowledge, and shows that small gains in per-step accuracy compound into much longer completable tasks (Section 2). Section 3.2 finds a self-conditioning effect. When chat histories are counterfactually seeded with injected errors, accuracy at turn 100 falls further as the injected error rate rises, beyond what long context alone explains (Result 3, Figure 5). Scaling model size does not remove this effect (Result 4), while Qwen3 thinking models do not self-condition (Result 5, Figure 6). Supports: an agent's own earlier deviations raise the odds of later ones, which is a plausible mechanism for drift compounding within one trajectory. Note that the Figure 5 caption says scaling "increases" self-conditioning, while the Result 4 text says only that scaling "does not mitigate" it. Cite the weaker wording.

### gu2025challenges: Challenges and Paths Towards AI for Software Engineering
Source checked: https://arxiv.org/abs/2503.22625, https://arxiv.org/html/2503.22625
This is a 75-page position and survey paper that maps AI-for-SE tasks, the open challenges, and directions for future work. Section 3.1 (Evaluation and Benchmarks) has an explicit "Construct Validity" paragraph. It says that while SWE-Bench comes close, "user experiences do not currently match rapid performance gains", partly because "many desiderata in software engineering cannot be described cleanly via automated unit testing." Section 3.3 ("Vague Specifications and User Misalignment", "Implicit constraints") gives the astropy-#14181 example, where SWE-Bench-evaluated models implemented only the read method when convention also required write. Gap we fill: the paper names the construct-validity gap between unit-test pass rates and developer intent, and our visible/hidden split measures that gap directly.
