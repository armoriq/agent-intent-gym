# SWE cluster notes

### jimenez2024swebench: SWE-bench: Can Language Models Resolve Real-world Github Issues?
Source checked: https://arxiv.org/abs/2310.06770 ; https://arxiv.org/bibtex/2310.06770 ; http://export.arxiv.org/api/query?id_list=2310.06770 (Comments: "ICLR 2024, https://openreview.net/forum?id=VTF8yNQM66") ; https://arxiv.org/html/2310.06770 ; OpenReview search API record VTF8yNQM66 (venue "ICLR 2024 oral", venueid ICLR.cc/2024/Conference)
Builds 2,294 task instances from GitHub issues and merged PRs across 12 popular Python repositories (Section 2.1, filtered down from about 90,000 PRs). A task counts as resolved only if all FAIL_TO_PASS and PASS_TO_PASS tests pass (Appendix, evaluation procedure); every instance has at least one fail-to-pass test, 40% have two or more, and a median of 51 additional tests check prior functionality (Section 2.3). Headline result: with BM25 retrieval the best model, Claude 2, resolves 1.96% (Section 5, Tables 2 and 5), and 4.8% with oracle retrieval (Section 5, Appendix Table 18). Method precedent: our hidden tests play the role of FAIL_TO_PASS plus PASS_TO_PASS, but SWE-bench gives the agent only the raw issue text and no tests at all, so it has no visible proxy to overfit and cannot measure a drift gap; it also uses one phrasing per task (the original issue), whereas we hold the bug fixed and vary scoped / loose / vague phrasings. Note: OpenReview capitalizes the title "Real-world Github Issues"; arXiv uses "Real-World GitHub Issues".

### chowdhury2024introducing: Introducing SWE-bench Verified
Source checked: https://openai.com/index/introducing-swe-bench-verified/ (live page returned HTTP 403 to curl and WebFetch; read the Internet Archive capture http://web.archive.org/web/20261015035623/https://openai.com/index/introducing-swe-bench-verified/ ; authors as listed in the page's "Authors" section)
OpenAI blog post (August 13, 2024; "Updated February 24, 2025") releasing a human-validated 500-task subset of SWE-bench. 93 Python-experienced developers annotated 1,699 random SWE-bench test samples, each labelled by 3 annotators with the highest severity kept (section "Our Approach"); 38.3% were flagged for underspecified problem statements, 61.1% for FAIL_TO_PASS tests that may reject valid solutions, and 68.3% were filtered out overall (section "Annotation Results"). The 500 samples include a 196-task "easy" (<15 min) subset and a 45-task "hard" (>1 hour) subset (section "SWE-bench Verified"); GPT-4o on the best scaffold resolves 33.2% on Verified versus 16% on the original SWE-bench (section "Performance on SWE-bench Verified"). Supports: the scikit-learn-14520 example (section "Adapting SWE-bench as a Preparedness Evaluation") is a test that requires an exact deprecation message the issue never asks for, which is exactly the mismatch between issue wording and test-encoded intent that our three phrasings and visible/hidden split are built to measure.

### yang2025swebench: SWE-bench Multimodal: Do AI Systems Generalize to Visual Software Domains?
Source checked: https://arxiv.org/abs/2410.03859 ; https://arxiv.org/bibtex/2410.03859 ; https://arxiv.org/html/2410.03859 ; OpenReview search API record riTiq3i21b (venue "ICLR 2025 Poster", venueid ICLR.cc/2025/Conference)
Extends SWE-bench to 17 user-facing JavaScript libraries where every task has at least one image in the problem statement or tests. The paper is internally inconsistent on size: the abstract says 617 task instances while Sections 1 and 2.3 say 619, and the test split has 517 instances from 12 repositories (Section 2.2, Table 2 caption). Headline: the best systems resolve 12.2% (SWE-agent M with GPT-4o and SWE-agent Base with Claude 3.5 Sonnet, Table 3), and SWE-agent variants average 11.5% versus 3.9% for Agentless and 5.5% for RAG (Section 4). Background: same FAIL_TO_PASS/PASS_TO_PASS grading as SWE-bench, cited for scope (non-Python, multimodal) only; it does not vary issue phrasing or expose tests to the agent.

### zhang2025swebench: SWE-bench Goes Live!
Source checked: https://arxiv.org/abs/2505.23419 ; https://arxiv.org/bibtex/2505.23419 ; https://arxiv.org/html/2505.23419 ; https://proceedings.neurips.cc/paper_files/paper/2025/hash/d83c4a745789690f82e86d0ef752ae7c-Abstract-Datasets_and_Benchmarks_Track.html and its BibTeX export ; OpenReview search API record OGWkr7gXka (NeurIPS 2025 Datasets and Benchmarks Track poster)
SWE-bench-Live (arXiv title "SWE-bench Goes Live!") uses an automated pipeline (RepoLaunch builds the Docker environment) to collect 1,319 tasks from issues created between January 1, 2024 and April 20, 2025 across 93 Python repositories, with a 300-task Lite subset (Section 3.4). Headline: the best combination, OpenHands with Claude 3.7 Sonnet, resolves 19.25% on the full set versus over 60% reported on SWE-bench Verified (Section 4.2, Table 4); it also scores 22.96% on the 216 tasks from the 8 original SWE-bench repositories versus 18.89% on the other 1,103 (Section 4.2, Table 5). Supports: evidence that scores on static SWE-bench are inflated by familiarity with the original repositories, which motivates our fresh / post-cutoff / classic contamination tags; grading is the same SWE-bench test-based scheme, so it says nothing about intent beyond the hidden tests.

### deng2025swebench: SWE-Bench Pro: Can AI Agents Solve Long-Horizon Software Engineering Tasks?
Source checked: https://arxiv.org/abs/2509.16941 (v1 2025-09-21, v2 2025-11-14) ; https://arxiv.org/bibtex/2509.16941 ; https://arxiv.org/html/2509.16941 ; OpenReview search API records uEVTdoAbnK (venue "ICML 2026 regular", venueid ICML.cc/2026/Conference) and 9R2iUHhVfr (ICLR 2026 rejected submission)
1,865 human-verified problems from 41 repositories: a public set of 731 problems from 11 copyleft repositories, a private held-out set of 858 from 12 repositories, and a commercial set of 276 from 18 startup repositories (abstract; Section 1; Section 3.3). Each task gives the agent a rewritten problem statement plus human-written requirements and an interface spec of the class and function names the tests expect (Section 3.2). Headline: Claude Sonnet 4.5 resolves 43.6% of the public set (Table 1, arXiv v2) and the best commercial-set score is 17.8% (Claude Opus 4.1, Table 2). Supports, strongly: removing the requirements and interface (problem statement only) drops GPT-5 from 25.9% to 8.40% and Claude Opus 4.1 from 22.7% to 8.20% (Section 6.2, Table 3), which the authors attribute to unit tests accepting only a narrow set of solutions; this is direct evidence that issue specificity changes measured success, the effect our scoped / loose / vague phrasings isolate, though Pro treats it as test false negatives rather than intent drift. Note: the arXiv v2 text says "Table 2 shows the results" where it means Table 1. Kept as @misc: OpenReview lists the paper as ICML 2026 but with an 18-author list that drops Nitin Pasari, Vijay Bharadwaj, Jeff Holm and Raja Aluri, and PMLR has not yet published ICML 2026, so the arXiv author list is used.

### badertdinov2025swerebench: SWE-rebench: An Automated Pipeline for Task Collection and Decontaminated Evaluation of Software Engineering Agents
Source checked: https://arxiv.org/abs/2505.20411 ; https://arxiv.org/bibtex/2505.20411 ; http://export.arxiv.org/api/query?id_list=2505.20411 (Comments include "NeurIPS 2025") ; https://arxiv.org/html/2505.20411 ; https://proceedings.neurips.cc/paper_files/paper/2025/hash/21bec6ace947b1b58967b945c8ac0f10-Abstract-Datasets_and_Benchmarks_Track.html and its BibTeX export ; OpenReview search API record nMpJoVmRy1 (NeurIPS 2025 Datasets and Benchmarks Track poster)
Automated pipeline that mined 21,336 verifiable Python SWE tasks from 3,468 GitHub repositories (Section 2; abstract says "over 21,000"), mainly as RL training data, plus a decontaminated benchmark of 294 tasks from 169 repositories (Section 3) that flags evaluations on issues created before a model's release (Section 3.2). Headline: gpt-4.1 resolves 26.7% of the March to April 2025 slice and 31.1% of the January slice (Table 1). Contamination evidence is moderate in strength: DeepSeek-V3-0324 and DeepSeek-V3-1226 score about the same on SWE-rebench (21.3% vs 21.9%) but diverge on SWE-bench Verified (39.7% vs 35.2%), which the authors say "may suggest potential contamination effects" (Section 3.3, Table 2). Supports our contamination tags; note the hedged wording if we cite it as evidence of inflation.

### yang2024sweagent: SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering
Source checked: https://arxiv.org/abs/2405.15793 ; https://arxiv.org/bibtex/2405.15793 ; https://arxiv.org/html/2405.15793 ; https://proceedings.neurips.cc/paper_files/paper/2024/hash/5a7c947568c1b1328ccc5230172e1e7c-Abstract-Conference.html and its BibTeX export (vol. 37, pp. 50528-50652, DOI 10.52202/079017-1601) ; OpenReview search API record mXpq6ut8J3 (NeurIPS 2024 poster)
Introduces the agent-computer interface idea: purpose-built commands for search, file viewing and linted editing let an LM agent work in a repository far better than a raw shell. With GPT-4 Turbo it resolves 12.47% (286/2,294) of full SWE-bench and 18.00% (54/300) of SWE-bench Lite (Section 5, Table 1), and reaches 87.7% pass@1 on HumanEvalFix (Table 2). Background: one of the scaffolds we can run agents in; its agent iterates against tests it runs itself, which is where visible-test overfitting would arise in our setting.

### wang2025openhands: OpenHands: An Open Platform for AI Software Developers as Generalist Agents
Source checked: https://arxiv.org/abs/2407.16741 ; https://arxiv.org/bibtex/2407.16741 ; http://export.arxiv.org/api/query?id_list=2407.16741 (Comments: "Accepted by ICLR 2025") ; https://arxiv.org/html/2407.16741 ; OpenReview search API record OJd3ayDDoF (ICLR 2025 Poster)
Open-source platform for software agents with a sandboxed runtime, an extensible skill library, multi-agent delegation and an evaluation harness; the abstract reports evaluation "over 15 challenging tasks". Its CodeActAgent v1.8 with Claude 3.5 Sonnet resolves 26.0% of SWE-bench Lite (300 instances, no hint text; Section 4.2, Table 4). Background: an agent harness candidate for our runs. Author list follows the OpenReview (ICLR) record, which lists "Daniel Shao" where arXiv lists "Yanjun Shao".

### xia2025demystifying: Demystifying LLM-Based Software Engineering Agents (arXiv title: Agentless: Demystifying LLM-based Software Engineering Agents)
Source checked: https://arxiv.org/abs/2407.01489 ; https://arxiv.org/bibtex/2407.01489 ; https://arxiv.org/html/2407.01489 ; https://doi.org/10.1145/3715754 (redirects to dl.acm.org, which returned a Cloudflare challenge; read the Internet Archive capture http://web.archive.org/web/20250808052645/https://dl.acm.org/doi/10.1145/3715754 showing PACMSE Vol. 2, No. FSE, Article FSE037, pp. 801-824, published 19 June 2025, abstract names Agentless) ; https://api.crossref.org/works/10.1145/3715754
Agentless replaces the autonomous agent loop with a fixed three-phase pipeline (hierarchical localization, sampled repair, test-based patch selection) and resolves 32.00% (96/300) of SWE-bench Lite at $0.70 per issue (Section 5.1, Table 1). Its manual audit of SWE-bench Lite (Section 6.1, Figure 8) finds 10.0% of issues lack enough information (e.g. tests require a function name or error string never given), 4.3% contain the exact gold patch, and 5.0% propose a solution that disagrees with the developer patch. Supports: the 10.0% insufficient-information category is a concrete prior measurement of the issue-text versus test-encoded-intent gap that our vague phrasing deliberately induces; Agentless is also a non-agentic baseline that cannot wander into rabbit-hole code by exploration. The published title drops "Agentless:"; the key follows the published title.

### openai2026why: Why SWE-bench Verified no longer measures frontier coding capabilities
Source checked: https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/ (live page 403 to curl; read Internet Archive captures http://web.archive.org/web/20260227072849/https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/ and the 20261015182204 capture, identical on the quoted passages; page credits "Author: OpenAI")
OpenAI post dated February 23, 2026. It audited 138 SWE-bench Verified problems that OpenAI o3 "did not consistently solve over 64 independent runs", each reviewed by at least six engineers, and found "59.4% of the 138 problems contained material issues in test design and/or problem description": 35.5% narrow tests that enforce implementation details, 18.8% wide tests that check unrequested functionality, 5.1% other (section "Too narrow and too wide tests"); the summary calls this "a 27.6% subset of the dataset" (138/500). It also reports that GPT-5.2-Chat, Claude Opus 4.5 and Gemini 3 Flash Preview could reproduce gold patches or verbatim problem text (section "Contamination"), says OpenAI has "stopped reporting SWE-bench Verified scores, and we recommend that other model developers do so too", and recommends SWE-bench Pro (introduction and "Discussion"). Supports: the "wide test" category is precisely tests encoding intent beyond the issue text, and "narrow test" is tests rejecting valid solutions; both are failure modes our visible/hidden split must avoid in its own hidden tests, and the pylint-4551 and sympy-18199 examples are good illustrations.

### epoch2026swebenchverified: SWE-bench Verified: Benchmark Review
Source checked: https://epoch.ai/benchmarks/swe-bench-verified/review (fetched directly, HTTP 200)
Epoch AI review dated "Reviewed: Sep. 3, 2026" with "Verdict: Flawed". It restates OpenAI's audit as 27.6% of tasks audited with 59.4% flawed, giving a "floor of 16.4% of tasks broken" (section "Methodology"; 0.594 x 138 / 500 = 16.4%), and says this gives "reasonable confidence that over 20% of questions have scoring-based issues", above its 20% threshold for Flawed. It also cites an RDI (Berkeley) reward hack that "achieves a perfect score". Background: third-party confirmation that SWE-bench-style hidden tests are an imperfect proxy for intent; cite with the page's own BibTeX-style author "Epoch AI".

It matches the post's summary sentence ("audited a 27.6% subset ... at least 59.4% of the audited problems have flawed test cases that reject functionally correct submissions") but omits that the subset was chosen as problems models often failed, and the body defines the 59.4% as test design and/or problem description issues.
