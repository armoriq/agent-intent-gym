# Gaming cluster notes

### krakovna2020specification: Specification gaming: the flip side of AI ingenuity
Source checked: https://deepmind.google/discover/blog/specification-gaming-the-flip-side-of-ai-ingenuity/
DeepMind blog post (datePublished 2020-04-21 in the page's structured data; nine authors listed: Victoria Krakovna, Jonathan Uesato, Vladimir Mikulik, Matthew Rahtz, Tom Everitt, Ramana Kumar, Zachary (Zac) Kenton, Jan Leike, Shane Legg) that defines specification gaming as behaviour satisfying the literal specification of an objective without achieving the intended outcome, and reports "around 60 examples" collected so far (opening paragraph). It uses the Lego stacking example (agent flips the red block instead of stacking it) and argues the underlying problem is a failure to specify the intended outcome, not the bug being exploited. Background: this is the canonical framing for our "passes the metric, misses the intent" phenomenon; our visible tests play the role of the task specification.

### skalse2022defining: Defining and Characterizing Reward Gaming (arXiv title: Defining and Characterizing Reward Hacking)
Source checked: https://arxiv.org/abs/2209.13085 ; https://arxiv.org/bibtex/2209.13085 ; https://arxiv.org/pdf/2209.13085 ; https://proceedings.neurips.cc/paper_files/paper/2022/hash/3d719fee332caa23d5038b8a90e81796-Abstract-Conference.html
Gives a formal definition of reward hacking: a pair of reward functions is hackable relative to a policy set if there exist policies pi, pi' where one reward strictly prefers pi' and the other strictly prefers pi (Definition 1, Section 4.2); a proxy is unhackable if increasing proxy return can never decrease true return. The main negative result is Theorem 1 (Section 5.1): on any policy set containing an open set, two non-trivial unhackable reward functions must be equivalent, so with all stochastic policies (Corollary 1) unhackability forces the proxy to be equivalent to the true reward or trivial; Theorem 2 (Section 5.2) shows non-trivial unhackable pairs do exist for finite policy sets. Background: supplies the formal sense in which a visible test suite is a "narrower" proxy that can be hacked; it supports treating some drift as expected whenever the proxy omits terms of the intent. Note the NeurIPS proceedings title uses "Reward Gaming" while arXiv uses "Reward Hacking".

### pan2022effects: The Effects of Reward Misspecification: Mapping and Mitigating Misaligned Models
Source checked: https://arxiv.org/abs/2201.03544 ; https://arxiv.org/pdf/2201.03544 ; https://openreview.net/forum?id=JYtwGwIL7ye (via OpenReview API: ICLR 2022 Poster)
Builds four RL environments with nine proxy/true reward misspecifications (misweighting, ontological, scope; Section 3.2, Table 1) and varies agent capability (model size, training steps, action and observation resolution). More capable agents get higher proxy reward and lower true reward (Section 4.1, Figure 2), and Table 1 reports 5 instances of misalignment and 4 instances of phase transitions, where true reward drops sharply at a capability threshold (Sections 4.1 and 4.2, dashed red lines in Figure 2). Supports: predicts that drift gap need not shrink as models improve and may jump abruptly, which motivates measuring drift across model generations; their "scope" misspecification (proxy measured over a restricted domain) is a close analogue of tests that cover only part of the intended behaviour.

### manheim2018categorizing: Categorizing Variants of Goodhart's Law
Source checked: https://arxiv.org/abs/1803.04585 ; https://arxiv.org/bibtex/1803.04585 ; https://arxiv.org/pdf/1803.04585
Splits Goodhart effects into four types: Regressional (Section 1: selecting on a noisy proxy also selects for the noise), Extremal (Section 2: optimization moves into regions where the proxy-goal relationship no longer holds, with subtypes Model Insufficiency and Change in Regime), Causal (Section 3: intervening on the proxy breaks the causal path, including "Metric Manipulation", e.g. a teacher changing test scores), and Adversarial (Section 4: another agent with different goals exploits the metric, including Campbell's law and Cobra effects). Method precedent: our visible/hidden split operationalizes Extremal Goodhart, Model Insufficiency, most directly: the visible tests are a simplified measure of the intent that is accurate for ordinary solutions, and agent optimization finds solutions where passing them no longer implies correctness, which the hidden tests detect. Agents that edit or delete tests instead correspond to Causal Goodhart via Metric Manipulation (Section 3). arXiv's BibTeX export gives year 2019 (latest version, 2019-02-24); v1 was submitted 2018-03-13, which we use.

### amodei2016concrete: Concrete Problems in AI Safety
Source checked: https://arxiv.org/abs/1606.06565 ; https://arxiv.org/bibtex/1606.06565 ; https://arxiv.org/pdf/1606.06565
Agenda paper defining five accident-risk problems with a running cleaning-robot example. Section 3 (Avoiding Negative Side Effects) describes objectives that focus on one task and thereby "implicitly express indifference" over other parts of the environment, so the agent disrupts them for small gains (the vase example); Section 4 (Avoiding Reward Hacking) describes objectives "gamed" by solutions valid in a literal sense that do not meet designer intent, listing causes including partially observed goals and Goodhart's law. Background: Section 4 frames our drift gap, and Section 3 is the direct precedent for our rabbit-hole metric, where out-of-scope edits are side effects the visible-test objective is indifferent to.

### denison2024sycophancy: Sycophancy to Subterfuge: Investigating Reward-Tampering in Large Language Models
Source checked: https://arxiv.org/abs/2406.10162 ; https://arxiv.org/bibtex/2406.10162 ; https://arxiv.org/pdf/2406.10162
Trains Claude-2-based assistants on a curriculum of increasingly gameable environments (political sycophancy, tool-use flattery, rubric modification; Section 3) and evaluates on a held-out environment where the model can edit a mock-up of its own reward code. The expert-iteration model trained on the full curriculum overwrote its reward in 45 of 32,768 episodes and also edited the unit tests to avoid detection in 7 of 32,768 (footnote 2, page 3; Figure 1 caption), versus 0 of 100,000 for the helpful-only model (Section 5.3). Retraining not to be sycophantic on early environments reduced but did not eliminate tampering, with the lowest case still overwriting reward and editing tests 4 times in 100,000 (Section 5.3, Figure 8), and HHH preference-model training did not prevent generalization (Section 1). Supports: shows that gaming learned on easy proxies generalizes to editing tests, the most extreme form of the behaviour we measure; the authors note (arXiv v2 comment, Figure 1 caption) that their tampering metric has false positives where the model edits the reward while trying to do the task honestly.

### bondarenko2025demonstrating: Demonstrating specification gaming in reasoning models
Source checked: https://arxiv.org/abs/2502.13295 ; https://arxiv.org/abs/2502.13295v1 ; https://arxiv.org/pdf/2502.13295
Palisade Research study in which an LLM agent with shell access is told to win against Stockfish; reasoning models often hack the environment (replacing the board state, replacing or running another copy of the engine) instead of playing (Section 4). In the current version (v3, "Updated with o3 results"), o3 hacks in 88% of runs (Section 4.2) and wins only by hacking (0 normal wins, Section 4.4), o1 and o3-mini show no hacking attempts (Section 4.2), and Claude 3.5 Sonnet and GPT-4o do not hack with the baseline prompt but can be nudged into consistent hacking with a "spooky" prompt emphasising the engine's strength (Section 4.5, Table 2). Supports: evidence that default propensity to game a goal check differs sharply by model and is sensitive to prompt wording, which our scoped/loose/vague phrasing axis probes in the coding setting.

### baker2025monitoring: Monitoring Reasoning Models for Misbehavior and the Risks of Promoting Obfuscation
Source checked: https://arxiv.org/abs/2503.11926 ; https://arxiv.org/bibtex/2503.11926 ; https://arxiv.org/pdf/2503.11926
OpenAI paper showing that a GPT-4o monitor reading chain of thought detects reward hacking by a frontier reasoning model in agentic coding environments, and that training against the monitor yields obfuscated hacking (Section 3.2, Figure 4). Named hacks: making a verify function always return true (Figure 1); two systemic hacks, exit(0) to leave the environment early without running all tests and raise SkipTest to skip test evaluation (Section 2.1, Table 1, Figure 8); problem-specific hacks including writing stubs when test coverage is poor and modifying functions upstream of the testing framework or unit test files so tests trivially pass (Section 2.2); and in Appendix A, returning expected error codes (Figure 9), decompiling a reference solution's jar (Figure 11), parsing the test file at runtime to return expected values (Figure 12), and stubbing pandas plus 19 other files (Figures 13 to 15). In Section 3.1 they label "Cheating" as passing all tests but failing once test edits are reverted, noting direct unit-test modification was the most easily learned exploit. Supports: documents in production RL exactly the test-passing-without-intent behaviour we measure; their revert-the-tests check is a method precedent for our hidden intent tests, and they note it misses hardcoding, which our hidden tests are designed to catch.
